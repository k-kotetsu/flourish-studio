## 1. デザイン原則

プロダクト原則（定義書15章）を、画面をつくるときの判断基準に翻訳したもの。迷ったらここに戻る。

### 原則1：評価に見せない

点数、順位、優劣を想起させる表現を画面に持ち込まない。ゲージ、偏差値、レーダーチャート、赤信号は使わない。状態は**段階**として示し、達成度としては示さない。

### 原則2：空白を欠落として描かない

未作成の領域は、グレーアウトやエラー色ではなく**破線**で示す。「未完成」「空欄」「未入力」という語を画面に出さない。

### 原則3：待ち時間にも言葉を置く

AI生成の待ち時間は、この製品では避けられない。無言のスピナーにせず、**いま何をしているか**を書く。

### 原則4：ユーザーの言葉を消さない

失敗・エラー・戻る操作で、ユーザーが書いた文字を消さない。破棄する場合は必ず先に確認する。

### 原則5：ひとつの画面に主要アクションはひとつ

選ばせる負荷を上げない。複数の選択肢を並べるときは、主・副の差を形で示す。

### 原則6：装飾で意味を作らない

色・アイコン・囲みは、意味を持つときだけ使う。同じ意味には同じ形を、違う意味には違う形を割り当てる。

## 2. カラー

### 2.1 考え方

**役割（トークン）で定義し、画面ごとに色を選ばない。** ダークモードはトークンの差し替えだけで成立させる。

配色の方向は「**設計図と園芸の交差**」。Flourish Mapは人生の設計図であり、同時に育てるもの。緑を帯びた紙のようなニュートラルに、彩度を抑えたセージグリーンを1色だけ載せる。彩度の高いグリーンにも、ミント系の明るいウェルネス配色にも寄せない。

### 2.2 トークン一覧

**基本トークン（指定値）**

| トークン | 役割 | ライト | ダーク |
|---|---|---|---|
| `--bg` | 画面の地 | `#F8F9F6` | `#151A18` |
| `--surface` | カード・入力欄の面 | `#FFFFFF` | `#1E2522` |
| `--primary` | 主要アクション・選択済み | `#52796F` | `#8EB7A8` |
| `--primary-soft` | 選択済みの面 | `#E2ECE7` | `#263C35` |
| `--text` | 本文・見出し | `#202522` | `#F1F4F2` |
| `--text-sub` | 補足・説明 | `#68736D` | `#A4AFA9` |
| `--border` | 装飾的な区切り線 | `#E2E6E3` | `#333D38` |

**派生トークン**

基本トークンだけでは足りない役割を補う。値はコントラスト比を満たすよう決めた。

| トークン | 役割 | ライト | ダーク |
|---|---|---|---|
| `--surface-sub` | 一段沈めた面（導入文など） | `#F4F6F3` | `#252D29` |
| `--text-faint` | 目盛りの端ラベルなど | `#828C86` | `#7F8A84` |
| `--control-border` | **操作部品の枠**（入力欄・ラジオ・目盛り） | `#7A847E` | `#6E7A74` |
| `--primary-ink` | `--primary` の上に載る文字 | `#FFFFFF` | `#12211B` |
| `--danger` | エラー | `#9E3520` | `#E8907B` |
| `--warning` | 注意 | `#7C5A12` | `#D9AC61` |

### 2.3 `--border` と `--control-border` を分ける理由

**`--border` は装飾専用。操作部品の枠には使わない。**

`--border`（ライト `#E2E6E3`）を地の上に置いたコントラスト比は **1.19**、ダーク（`#333D38`）でも **1.56** で、いずれも 3:1 に届かない。区切り線としては軽やかで正しいが、WCAG 1.4.11 は入力欄・ラジオ・目盛りといった操作部品の境界に 3:1 を要求する。

| 用途 | 使うトークン |
|---|---|
| カードの外周、セクションの区切り線 | `--border` |
| 入力欄、ラジオ、チェックボックス、目盛りのマス | `--control-border` |

装飾線まで濃くすると画面が重くなり、逆に操作部品を薄いままにすると弱視の人が枠を見つけられない。**役割で分けることで両立させている。**

### 2.4 コントラスト比（実測値）

| ペア | ライト | ダーク | 基準 |
|---|---|---|---|
| 本文 on 地 | 14.73 | 15.90 | 4.5 |
| 本文 on 面 | 15.57 | 14.12 | 4.5 |
| 補足 on 地 | 4.66 | 7.78 | 4.5 |
| 補足 on 面 | 4.93 | 6.91 | 4.5 |
| 補足 on 沈めた面 | 4.53 | 6.25 | 4.5 |
| 微弱 on 地 | 3.29 | 4.92 | 3.0 |
| Primary文字 on 面 | 4.86 | 7.07 | 4.5 |
| Primary文字 on 地 | 4.60 | 7.95 | 4.5 |
| ボタン文字 on Primary | 4.86 | 7.54 | 4.5 |
| 本文 on Primary Soft | 12.89 | 10.65 | 4.5 |
| エラー on 地 | 6.66 | 7.30 | 4.5 |
| 注意 on 地 | 5.97 | 8.40 | 4.5 |
| 操作部品の枠 on 地 | 3.66 | 3.94 | 3.0 |
| 操作部品の枠 on 面 | 3.87 | 3.50 | 3.0 |

**ライトモードは余裕が小さい。** 補足文（4.66）、Primary文字（4.60）、ボタン文字（4.86）はいずれも基準を数%上回るだけ。**これらのトークンを1段でも明るくすると基準を割る。** 変更時は必ず再計測する。

### 2.5 Primary を使ってよい場所

| 使う | 使わない |
|---|---|
| 主要アクションのボタン | 見出し |
| 選択済みの目盛り・ラジオ | 本文中の強調 |
| プログレスバーの進捗部分 | カードの枠 |
| 成長段階の現在位置 | アイコンの塗り分け |
| 領域カードの選択状態 | 4領域の区別 |
| リンクテキスト | 装飾 |

**1画面に Primary が3箇所以上出たら、設計を疑う。**

### 2.6 4領域の色分けはしない

Career / Financial / Physical / Social に固有色を割り当てない。4領域は同列であり、色で性格づけするとバランスの解釈が生まれる。区別は**アイコンと英語ラベル**で行う。

## 3. ダークモード／ライトモード

### 3.1 対応方針

| 項目 | 決定 |
|---|---|
| 既定 | **OSの設定に追従する** |
| 手動切り替え | **できる**。ユーザーの選択はOS設定より優先する |
| 保存 | 選択はアカウントに紐づけて保存する（端末をまたいで一致させる） |
| 未選択時 | OS設定に追従し続ける |

### 3.2 切り替えUIの置き場所

MVPには設定画面がないため、**ホーム（S-41）のヘッダー右端にトグルを置く。**

| 状態 | アイコン |
|---|---|
| システムに追従（既定） | **半分が塗られた円** |
| ライト固定 | **太陽** |
| ダーク固定 | **月** |

いずれも線画。7.6 のアイコン規約に従う。

タップで **自動 → ライト → ダーク → 自動** と循環させる。3状態を1つのトグルで扱うため、押すたびに現在の状態をラベルで示す。

ホーム以外の画面にはトグルを置かない。フロー中に見た目が変わる操作をさせない。

### 3.3 実装ルール

- 色は**必ずトークン経由**で指定する。要素に直接カラーコードを書かない
- ダークはライトの単純な反転にしない。トークンごとに個別に決める（2.2の表がその結果）
- 画像・イラストを入れる場合は、両テーマで成立するか個別に確認する
- 切り替え時のアニメーションは付けない（`prefers-reduced-motion` の考慮対象を増やさない）

## 4. タイポグラフィ

### 4.1 書体

| 用途 | 書体 |
|---|---|
| 和文（本文・見出し） | システムフォント（`Hiragino Sans` → `Noto Sans JP` → `Yu Gothic` → `sans-serif`） |
| 欧文（領域名・ラベル） | **Instrument Sans**（ラテン文字のみ読み込む） |
| 数字・ID | `font-variant-numeric: tabular-nums` を指定 |

**和文にWebフォントを使わない。** 日本語書体は数MB規模になり、初回表示が遅れる。現在地レポートは「気軽に試せる入口」であり、待たせると入口の役目を果たさない。

**欧文だけWebフォントにする。** Career / Financial / Physical / Social は画面上で繰り返し現れる要素であり、ここに専用書体を当てると和文との差が生まれ、領域名がラベルとして立つ。ラテン文字のみのサブセットなら数十KBに収まる。

### 4.2 タイプスケール

| 役割 | サイズ | ウェイト | 行間 | 使う場所 |
|---|---|---|---|---|
| あだ名 | 28px | 700 | 1.35 | S-16のみ |
| 画面見出し | 20px | 700 | 1.45 | ありたい姿、理想の状態 |
| セクション見出し | 16px | 600 | 1.5 | 領域名、レポートの小見出し |
| 本文 | 15px | 400 | 1.8 | 質問文、AI出力、説明 |
| 補足 | 13px | 400 | 1.7 | ボタン下の理由、免責 |
| ラベル | 11px | 600 | 1.4 | 「満たされている点」などの見出し（字間 .08em） |

- 見出しには `text-wrap: balance` を指定する
- 本文の1行は**全角30〜35文字**を上限とする
- **文字サイズの拡大設定に追従する。** 固定pxで組んでも、ユーザーのブラウザ設定で拡大されたときに崩れないことを確認する

## 5. レイアウト

### 5.1 寸法

| 項目 | 値 |
|---|---|
| 基準幅 | 375px |
| 検証幅 | 430px |
| 最大幅（デスクトップ） | 430px（中央寄せ） |
| 左右の余白 | 16px |
| ヘッダー高 | 56px |
| プログレスバー高 | 4px（ヘッダー直下） |
| 下部固定ボタン高 | 56px（＋セーフエリア） |
| 最小タップ領域 | 44 × 44px |
| 角丸 | カード 9px ／ ボタン 8px ／ 入力欄 7px |

### 5.2 デスクトップ

**アプリ本体は、モバイルレイアウトを中央寄せで表示する。** デスクトップ専用のレイアウトは作らない。MVPで検証したいのは体験が成立するかであり、広い画面を活かすことではない。左右は地の色で埋める。

### 5.2.1 公開サイトだけは例外

**トップページ（S-01）と記事（K-01 / K-02）は、この制限を適用しない。**

| 項目 | 値 |
|---|---|
| 最大幅 | 960px |
| 本文の最大幅 | 640px |
| セクション背景 | 全幅に敷く |

公開サイトは**集客が目的で、PCからの流入を受ける。** 430px に収めると余白ばかりの画面になり、目的に反する。アプリ本体（S-11以降）は 430px 中央寄せのまま変えない。

### 5.3 間隔

- 兄弟要素の間隔は `gap` で取る。個別のマージンを積まない
- 縦の間隔は 6 / 10 / 14 / 18 / 24px から選ぶ
- 横スクロールが必要な要素は、その要素だけをスクロールさせる。**ページ本体を横スクロールさせない**

## 6. ナビゲーション

### 6.1 構造

**タブバーは置かない。ホーム（S-41）を唯一のハブとする。**

MVPで並列に置ける機能はホームと振り返りだけで、Knowledge・Support Toolsはともに準備中。タブバーを置くと中身のないタブが並ぶ。

| 目的地 | 到達手段 |
|---|---|
| ホームへ戻る | ヘッダーの「‹ 戻る」、またはフロー完了時の自動遷移 |
| Weekly Reflection | ホームのWR導線（目標0個で無効） |
| 各領域 | ホームの領域カード |
| Knowledge / Support Tools | ホームのカード（準備中・タップ不可） |

### 6.2 ヘッダーの型

| 画面の種類 | ヘッダーの内容 |
|---|---|
| ハブ（S-41） | サービス名＋テーマ切替トグル。戻るを置かない |
| フロー内 | 「‹ 戻る」＋プログレスバー＋ステップ番号 |
| フローの入口（S-11 / S-12 / S-51 / S-61） | 「× 中断」＋プログレスバー |
| 単独の画面（S-57 / S-58） | 「‹ 戻る」＋画面名。プログレスバーなし |
| 生成中 | 戻るを置かない（失敗時のみ本文に戻り導線） |

### 6.3 プログレスバー

| フロー | ステップ数 | 対象画面 |
|---|---|---|
| 現在地レポート | 6 | S-12 × 4領域 → S-14 → S-16 |
| ありたい姿 | 4 | S-31 → S-32 → S-34 → S-35 |
| 領域作成 | 5 | S-51 → S-52 → S-54 → S-55 → S-56 |
| Weekly Reflection | なし | 1画面で完結するため表示しない |

**生成中画面はステップに数えない。** 待ち時間はユーザーの作業ではない。

## 7. 共通コンポーネント

### 7.1 ボタン

| 種類 | 見た目 | 使う場所 |
|---|---|---|
| 主要 | `--primary` 地＋`--primary-ink` | 1画面に1つ |
| 副次 | 透明地＋`--control-border` の枠 | 主要と並べるとき |
| テキスト | 枠なし・`--text-sub` | 「対話に戻る」など逃げ道 |
| 無効 | `--surface-sub` 地＋`--text-faint` | 条件を満たさないとき |

**無効ボタンは消さずに残す。** 押せない理由を直下に補足として置く。何が起きているか分からない画面にしない。

### 7.2 中断の確認ダイアログ

「× 中断」を押したときは**必ず挟む**。未確定の入力は保存されないため。

| 要素 | 内容 |
|---|---|
| 見出し | ここでやめますか？ |
| 本文 | いま中断すると、ここまで選んでいただいた内容は残りません。またいつでも、最初から始められます。 |
| 主ボタン | つづける（閉じて元の画面へ） |
| 副ボタン | やめる（トップページへ） |

**「つづける」を主ボタンにする。** 誤操作で失う側を既定にしない。

「‹ 戻る」はフロー内の1つ前に戻るだけなので、ダイアログを出さない。

### 7.3 下部固定バー

| 種類 | 使う画面 |
|---|---|
| 主要アクション1つ | S-12 / S-16 など |
| 入力欄＋送信 | S-32 / S-52 |
| なし（本文内にボタン） | S-41 / 生成中画面 |

### 7.4 生成中画面

| 要素 | 内容 |
|---|---|
| インジケータ | 動いていることを示す |
| 進行メッセージ | **何をしているかを具体的に書く** |
| 失敗時 | 同じ画面の中身が入れ替わる。**別画面へ遷移しない** |
| 再試行 | 手動のみ。**自動リトライしない** |
| フォールバック | **定型文で埋めない**（ユーザーの言葉を扱う機能のため） |

該当画面：S-13 / S-15 / S-33 / S-53 / S-62

### 7.5 選択肢の向き

**ポジティブを右（縦積みの場合は下）に置く。** 全画面で統一する。

| 形式 | 向き |
|---|---|
| 横並びの目盛り | 左＝満たされていない → 右＝満たされている |
| 縦積みの選択肢 | 上＝まだこれから → 下＝しっかり動けている |

目盛りの両端にのみラベルを置き、5段階すべてに全文ラベルを付けない。導入文に「右にいくほど、満たされている状態です」を添えて、向きを言葉でも示す。

### 7.6 アイコン

| 項目 | 決定 |
|---|---|
| スタイル | **線画（アウトライン）。** 塗りつぶしを使わない |
| 線幅 | 1.6px（24pxグリッド） |
| 角の処理 | 線端・接合部ともに丸める |
| 色 | `currentColor` で継承する。アイコン単体に色を持たせない |
| 実装 | インラインSVG。アイコンフォントや画像を使わない（テーマ切り替えに追従させるため） |

**4領域のアイコンは既製セットから選んでよい。** Career・Financial・Physical・Social は一般的な概念であり、描き起こす必要がない。

**成長段階（種・芽・苗・木）は描き起こす。** 既製のアイコンセットに、この4段階が揃った組は存在しない。**4つが並んだときに成長の連続が読み取れることが要件**であり、別々のセットから寄せ集めると段階に見えない。

| 段階 | 形の方針 |
|---|---|
| 種 | 地中の一粒。縦の線を1本だけ持つ |
| 芽 | 双葉。左右に開く |
| 苗 | 茎が立ち、葉が2枚。地面の線を引く |
| 木 | 樹冠と幹。枝を2本持つ |

高さの重心を段階ごとに上げていき、並べたときに右へ伸びていくように見せる。

### 7.7 成長段階の表示

段階名を1つだけ示しても、4段階のどこなのかが伝わらない。**種・芽・苗・木の4つをすべて並べ、該当する段階だけを `--primary` で塗る。**

| 要素 | 内容 |
|---|---|
| 軸名 | 言語化度 ／ コミット度 |
| 軸の説明 | 各軸に1行添える |
| アイコン | 線画で描き起こす（7.6参照）。4つが並んだときに成長の連続が読み取れること |
| 数値 | **出さない** |

## 8. 文章のトーン

### 8.1 語り口

**指示ではなく、声かけの語り口にする。** 内面を扱うサービスであり、正しさを教える立場に立たない。

| 避ける | 使う |
|---|---|
| 〜してください | 〜してみてください |
| 〜してはいけません | 〜しなくて大丈夫です |
| 確認してください | 確かめてみてください |
| 〜と書かれていました | 〜と書いてくださいました |
| 保存されません | 残りません |
| 実施する／回答する | やってみる／答える |

- 硬い漢語より和語を選ぶ
- 否定形を重ねない
- ユーザーの入力に触れるときは、受け取った側の言葉づかいにする
- ただし**丁寧すぎて回りくどくならない**。一文は短く保つ

### 8.2 感嘆符（！）

明るさを出すために使う。ただし多用すると軽くなり、内面を扱う場面で信頼を損なう。

| 使う場面 | 使わない場面 |
|---|---|
| 何かを終えた瞬間 | 質問文・選択肢 |
| 次へ進む呼びかけ | 気になっている点の記述 |
| 満たされている点を伝えるとき | エラー・失敗の表示 |
| | あだ名と免責の一文 |

**1画面につき多くて2つ。** 連続して置かない。

### 8.3 使わない語

| 語 | 理由 |
|---|---|
| 診断 | 結果を受け取るだけのサービスに見えるため |
| 未完成・空欄・未入力 | 育てる場所として表現するため |
| 頑張っていますね・素晴らしい | 評価する語のため（承認は具体的に行う。定義書 14.3） |

- 断定を避け「〜かもしれません」を使う（あだ名を除く）
- 広告・商品への誘導を混ぜない
- 一人称・二人称を過剰に使わない

### 8.4 エラー文

| ルール | 内容 |
|---|---|
| 何が起きたか | 書く |
| どうすれば直るか | 書く |
| 入力が残っているか | 残っている場合は明記する |
| 謝罪 | 書かない |
| 感嘆符 | 使わない |

## 9. アクセシビリティ

**WCAG 2.1 AA 相当を目標とする。**

| 項目 | 基準 |
|---|---|
| 文字のコントラスト | 4.5:1 以上（大きい文字は 3:1） |
| 操作部品の枠 | 3:1 以上（`--control-border` を使う） |
| タップ領域 | 44 × 44px 以上 |
| フォーカス | キーボード操作時に必ず可視のリングを出す |
| 文字サイズ | ユーザーの拡大設定に追従する |
| 動き | `prefers-reduced-motion` に対応する |
| 色だけに依存しない | 選択済み・エラーは、色に加えて形や文言でも示す |

**色だけで意味を伝えない。** 目盛りの選択済みは `--primary` で塗るが、それだけでなく枠線も変える。エラーは色に加えて文言で示す。

## 10. モーション

### 10.1 方針

**動きは積極的に使う。**

考えることの多いサービスであり、放っておくと固く重い印象になる。少しでも楽しく、前に進んでいる感覚を持ってもらうために、動きを設計要素として使う。

ただし、どこに使うかで意味が変わる。

> **「進んだ手ごたえ」には使う。「考えている時間」には使わない。**

内面を書いている最中や、結果を読んでいる最中に画面が動くと、集中が切れて急かされているように感じる。動かすのは**節目**に限る。

### 10.2 使う場所

| 場面 | 動き | 意図 |
|---|---|---|
| あだ名の登場（S-16） | 前置き → あだ名 → 「でしょうか。」の順に間を置いて現れる | この製品でいちばん軽い場面。ここだけ演出に時間を使う |
| 成長段階の点灯（S-16 / S-41） | 種から順に灯り、現在地で止まる | 「いまここまで来た」を静止画より短時間で伝える |
| ホームの立ち上がり（S-41） | ありたい姿 → 4領域 → 振り返り導線 の順に90msずつずらす | 情報の階層と現れる順序を一致させる |
| 生成中（全待ち画面） | 芽のアイコンをゆっくり拡縮（2.6秒周期） | 待たせている時間を、育っている時間として見せる |
| 選択したとき | チップ・目盛りがわずかに沈んで戻る | 触れた手ごたえを返す |
| 画面遷移 | フロー内は前進＝左へ、戻る＝右へスライド | 進む方向を身体で覚えられるようにする |
| プログレスバー | 領域をひとつ終えるたびに伸びる | 進んだ量を目で見せる |
| 目標の確定（S-56） | 確定したカードが一度だけ小さく跳ねる | 節目を祝う。連発しない |

### 10.3 使わない場所

| 場面 | 理由 |
|---|---|
| 自由記述の入力中 | 書いている手を止めさせない |
| レポート本文を読んでいる最中 | 読む速度をこちらで決めない |
| エラー・失敗の表示 | 状況と合わない。静かに出す |
| 選択式に答えている最中 | 24問・25項目を淡々と進めたい場面 |
| ループする装飾 | 生成中のインジケータ以外に、常時動き続けるものを置かない |

### 10.4 動きの規定

| 項目 | 値 |
|---|---|
| 基本の長さ | 400〜550ms（要素の登場）／ 200ms（触れた反応） |
| 連続表示のずらし幅 | 90〜160ms |
| イージング（登場） | `cubic-bezier(.2, .85, .25, 1)` |
| イージング（跳ね） | `cubic-bezier(.34, 1.56, .5, 1)` |
| 生成中の呼吸 | 2.6秒周期。速いと急かされている感じになる |
| 1画面あたりの演出 | 登場アニメーションは**1連鎖まで**。複数を同時に走らせない |

### 10.5 動きを止める配慮

`prefers-reduced-motion: reduce` が指定されているときは、**すべてのアニメーションを止め、最終状態を即座に表示する。** 透明度0のまま残さない。

テーマ切り替えにはアニメーションを付けない。色が動くと画面全体がちらついて見えるため。

## 11. スケルトン表示

**使わない。**

長い生成には独立した生成中画面（7.4）があり、通常のデータ取得は待ち時間が短い。スケルトンを足すと、**待たせている場所が2種類あるように見える。**

読み込み中は何も出さず、取得できてから描画する。
