# 文章のトーン

内面を扱うサービスであり、**正しさを教える立場に立たない。** 迷ったらこの1点に戻る。

## 語り口

指示ではなく、声かけにする。

| 避ける | 使う |
|---|---|
| 〜してください | 〜してみてください |
| 〜してはいけません | 〜しなくて大丈夫です |
| 確認してください | 確かめてみてください |
| 〜と書かれていました | 〜と書いてくださいました |
| 保存されません | 残りません |
| 実施する／回答する | やってみる／答える |

- 硬い漢語より和語を選ぶ
- 否定形を重ねない
- **一文は短く保つ。** 丁寧すぎて回りくどくしない
- 断定を避け「〜かもしれません」を使う（あだ名は例外）
- 一人称・二人称を過剰に使わない

## 絶対に使わない語

```
診断  未完成  空欄  未入力  頑張っていますね  素晴らしい  よくできています
```

- 「未作成の領域」は **「これから育てる領域」「まだ手をつけていない場所」**
- 「診断」ではなく **「現在地レポート」**

## 感嘆符

**1画面につき多くて2つ。連続して置かない。**

| 使ってよい | 使わない |
|---|---|
| 何かを終えた瞬間 | 質問文・選択肢 |
| 次へ進む呼びかけ | 気になっている点の記述 |
| 満たされている点を伝えるとき | エラー・失敗の表示 |
| | あだ名と免責の一文 |

## エラー文

| 書く | 書かない |
|---|---|
| 何が起きたか | **謝罪** |
| どうすれば直るか | **感嘆符** |
| 入力が残っているかどうか | 技術的な原因 |

```
✕ エラーが発生しました。申し訳ございません。
✕ AI生成に失敗しました！もう一度お試しください！
○ うまく作れませんでした。書いていただいた内容はそのまま残っています。
  もう一度試してみてください。
```

サーバは文面を持たない。**API のエラー `code` からクライアントが文面を決める**（`09_API設計` 2.3）。

## 承認・褒め方

AIの出力とUI文言の両方に適用する。

| ルール | 内容 |
|---|---|
| 対象 | 人格や能力ではなく、**言葉にできたこと・実際に取った行動**を認める |
| 方法 | ユーザーが書いた言葉を引いたうえで、どこが良かったのかを示す |
| 終わり方 | **承認だけで終えない。** 必ず問いか次の行動につなげる |
| 頻度 | 毎回褒めない |
| 前提 | **書かれていないことを褒めない。** 程度を誇張しない |

```
✕ 素晴らしいですね。
○ 「まわりが安心して力を出せるように」と書かれていました。
  ここは自分の言葉になっていると思います。それはどんな場面で感じたことですか。
```

## 売らない

**商品・サービス・アプリ・書籍・広告への言及を、有料無料を問わず一切書かない。** アドバイスは「今週から無料で始められること」に収める。

```
✕ 家計簿アプリを使ってみるのはどうでしょう。
○ まずは1週間だけ、何にいくら使ったか眺めてみるのはどうでしょう。
```

医療・法律・税務・投資の専門的助言や断定もしない。

## 例外：あだ名（S-16 のみ）

**この1箇所だけ「断定を避ける」を適用しない。** 言い切ってよい。ただし：

- 10〜20文字程度の名詞句または短い言い切り
- **「〜人」「〜タイプ」で終えない**
- 状態を言い表す。能力・人格・容姿を評価しない
- 収入の多寡・病気そのものを笑いの対象にしない
- 「〜でしょうか」の形に収め、直下に免責を必ず添える
